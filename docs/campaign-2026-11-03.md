further workers, alter other workers' files, update bullseye, or use a shared
Cargo target directory. Limit build concurrency per worker to avoid exhausting

## Execution and acceptance

1. Restore a pinned Java source/JAR reference compatible with recorded fixtures;
   record its revision, JAR hash, Java/Graphviz versions and relevant font setup.
   The documented source checkout was missing during assessment. CI's historical
   1.2025.2 pin differs from reviews naming 1.2026.3beta6; resolve provenance,
   never regenerate references wholesale to make tests pass.
2. Repair mechanical failures and wire existing suites into standing gates.
   Existing product/evidence failures remain visible; never mask them with
   skip logic, baseline reductions, changed tolerances, or permissive verdicts.
3. Cluster failures by causal mechanism. A parity change requires a committed
   Java/Rust causal account before production edits. Account commits precede
   implementation commits and name at least two perturbation axes.
4. Start a fresh independent checker task for each candidate mechanism. It
   audits source and changed constants, preserves every counterexample, runs
   freshly generated Java comparisons, and authors the review record. A
   rejected mechanism remains rejected until independently rechecked.
5. Integrate reviewed changes in small batches and rerun both parity tiers,
   guards, perturbations, unit and CLI tests. Ratchet only verified gains,
   preserving all existing evidence. Review-record schema repair must preserve
   historical identity, commands, failures and verdicts; never invent evidence.
6. Reserve the final three hours for stabilization and whole-batch validation.
   Land on local master only when required gates pass. Otherwise retain the
   integration branch and report exact remaining failures without claiming T14.

Planning windows: hours 0-3 reference/gate restoration; 3-6 causal triage and
work packets; 6-18 concurrent maker/checker cycles; 18-22 integration repair;
22-25 final validation. These are allocations, not a promise that unknown
mechanism defects can all be eliminated in a day.

Primary targets are T14.6, T15.3 and T15.9 for trustworthy verification, then
T14.4 for mechanism parity. T14.3 needs a current fallback-coverage assessment,
not the obsolete claim that FTile is inert. T14.8's font/reference decision is
